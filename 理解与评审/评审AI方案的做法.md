# 评审 AI 方案的做法

**核心：用需求尺度、成熟做法和具体反例压测方案，并继续追问回答中新出现的做法与假设。**

适用：已理解方案后，按当前最可疑之处选问；优先检查跨切片、批次或阶段时刚好卡在上限的情况。`xxx` 指你认为更合适的具体方案或做法。

尚未理解方案时，先用[理解 AI 方案的提示词](理解AI方案的提示词.md)厘清解法与边界；具体追问过程见[理解 AI、质疑 AI 实例](../治理与实例/理解AI、质疑AI实例.md)。

## 做法

### 1. 核对关键尺度是否撑得住需求

不符合的典型样子：某算法只能处理 6 个单位，超过 6 个则无法处理；当前切片是 6 个单位，但后续切片很快要提升到 30 个。尤其要检查跨切片情况。

可直接丢给 AI：

```
请核对方案中关键尺度（单位数量、算法层数等）的适用范围是否符合需求。
如果上限刚好等于当前切片/批次规模，请单独评估后续扩到更大规模、以及跨切片时是否仍然成立。
不符合需求时，明确指出卡在哪一个尺度上。
```

### 2. 发现没用 xxx 时，追问为什么不用

前提：你已经看出 AI 方案明显没有使用某个更合适的方案、办法或方式。没有这个前提就不要空问。

可直接丢给 AI：

```
为什么不使用 xxx 方案 / 办法 / 方式？
请对比当前方案和 xxx：适用边界、复杂度、和本需求的匹配程度。
```

### 3. 用例子推演，用反例压方案

举例子推演，并举出可能的反例，让 AI 用它自己的方案评估能否满足。问到具体位置、顺序、相对关系，看会不会自相矛盾。

可直接丢给 AI：

```
请评估以下场景：a 移动到了 x，b 在 a 的右侧。
按照你的方案能否处理？是否有矛盾？
如果能处理，请逐步推演；如果不能，指出方案在哪一步失效。
```

场景按你的业务替换。关键是：具体、可判定对错，而不是再让它讲一遍原理。

### 4. 刨根问底

回答出现新步骤、假设或边界时继续追问，直到反例和矛盾被解释清楚，或方案承认失效。

可直接丢给 AI：

```
针对你刚才说的做法，继续质疑，不要只复述原方案。
1. 给出可能让该做法失效的反例。
2. 指出做法内部、或做法与需求之间的矛盾点。
3. 指出明显违背事实的项（和已知需求、数据、物理/业务约束不符的说法）。
4. 对每个反例 / 矛盾 / 违背事实项：按你的方案逐步推演，说明能否处理；不能处理就承认失效点。
下一次回答里如果又出现新的做法或假设，继续按上面几条质疑。
```
