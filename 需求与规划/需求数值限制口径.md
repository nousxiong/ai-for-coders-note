# 需求数值限制口径

**核心：先区分必须满足的验收边界与可协商的数值目标；前者不可自行放宽，后者不必过早定死。**

适用：与 AI 协商 spec 中的上下限或数值范围时，尤其在 TDD 中，避免把可协商目标误写成硬性测试门禁。

划分交付单位时的相关做法见[功能拆分](功能拆分.md)。

## 做法

### 1. 对可协商目标写成软约束

可直接丢给 AI：

```
这条数值限制按软约束处理：尽量满足。如果难以实现，或数学计算上难以计算，允许不满足，并在结果里说明实际取值和原因。不要为了硬凑这个口径把设计做复杂。
```

### 2. 必须满足的边界无法实现时，上报人工

可直接丢给 AI：

```
这条数值限制是必须满足的验收边界。如果发现无法满足（难以实现，或数学计算上难以计算），不要自行放宽，也不要把设计做复杂去硬凑。停下来说明：卡在哪、为什么算不出来或实现不了、你考虑过的做法，然后等人工裁决。
```
